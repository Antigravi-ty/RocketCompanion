# Global instructions
Limit the amount of comments you put in the code to a strict minimum. You should almost never add comments, except sometimes on non-trivial code, function definitions if the arguments aren't self-explanatory, and class definitions and their members.

Do not remove existing comments unless they are directly related to what you are changing.

## Referring to code in bugs, reviews and commit messages

- **Reference a name, not a position.** This text outlives the code it describes, so cite a selector, function, class, pref or flag name; name a file without a line, and avoid positional phrasing ("the rule above X").

## Code Style
- Our style guide forbids the use of emoji.
- Every file in this repository—including source code, UI strings, comments, console output, documentation, and commit messages—must be written strictly in English.
- **Standalone Commits & Zero Legacy Baggage**: Treat every commit as a standalone version. Do not maintain backward or forward compatibility shims, deprecated fallbacks, dead code, or pure re-export barrel files (`index.js` facades). Prioritize code clarity, interpretability, and native engineering quality above all else.
- **Self-Explanatory Naming**: All variables, functions, classes, and modules must use clear, semantic, self-explanatory names. Meaningless single-letter or obfuscated identifiers are strictly forbidden, except for standard mathematical and graphics conventions.

## Architecture Boundaries
- Maintain zero circular dependencies across the codebase.
- Never embed binary or static assets inline in source code via Base64, Data URIs, or byte/hex arrays. Place runtime-fetched static assets in `public/` (mounted as a Git submodule linked to `RocketCompanionStatics`) and co-locate module-coupled binaries with their owning source module.
- `src/physics/core.js` and `src/physics/core.wasm` are auto-generated by Emscripten from the physics C++ source. Do not manually edit or refactor `src/physics/core.js`.
- Maintain unidirectional dependencies: core simulation and engine layers must never import from the UI presentation layer; `src/stores` must only depend on `src/config` (never importing from `camera`, `network`, `physics`, `entities`, `game`, or `ui-system`), and `src/config` must remain pure configuration without importing runtime subsystems.
